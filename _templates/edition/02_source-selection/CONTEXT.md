# 02_source-selection: choose candidate material

Room: `rooms/01-editorial/`

## One job

Produce a small, verified candidate set worth deeper research for this audience.

## Inputs

### Run-specific working inputs

- `../01_intake/output/assignment.md`
- candidate material and performance evidence named by the profile

### Stable references

- `publications/{{publication_id}}/source-contract.md`
- candidate-discovery binding from `skill-bindings.md`
- `references/output-contract.md`
- `_shared/approval-contract.md`
- any stage-specific rule or pointer explicitly added under `references/`

## Do not load

Do not load drafting, visual, packaging, or delivery procedures. Do not research
every available candidate in depth before screening.

## Process

1. Gather candidates only from approved sources or supplied material.
2. Verify dates, identifiers, and source locations.
3. Check freshness, prior coverage, duplication, audience fit, credibility, and
   obvious legal or reputational risk.
4. Rank or group candidates using the publication's stated criteria.
5. Preserve rejected candidates and reasons without treating them as approved
   evidence.

## Outputs

- `output/candidate-set.md`
- `output/stage-receipt.md` after the exit gate passes

Follow `references/output-contract.md` for the exact file fields. Do not create
the stage receipt until the exit gate passes.

## Exit gate

The ranked set passes the publication's freshness, duplication, source,
audience-fit, risk, and minimum-quality rules. Continue with the strongest
candidate set without routine human selection.

## Failure and fallback

If no candidate clears the publication threshold, record a thin-edition result
and use only the fallback allowed by the source contract. Do not manufacture a
story to keep cadence.
