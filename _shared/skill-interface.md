# Skill interface

The newsletter engine defines capability slots. A publication profile binds
each required slot to one canonical skill, lane, agent, script, or human
procedure. The engine does not copy those implementations.

| Capability slot | Used in | Binding must explain |
|---|---|---|
| candidate discovery | source selection | where candidates come from and how freshness and duplication are checked |
| research and source verification | research | source hierarchy, claim ledger, URL or file readback |
| editorial judgment | routing | audience fit, thesis selection, and unused-item routing |
| newsletter writing | draft | voice, structure, length, citations, and output format |
| factual and risk review | quality review | claims, legal risk, prohibited language, and release threshold |
| visual production | draft or package | when required, brand rules, generation route, and visual inspection |
| subject and packaging | package | performance evidence, metadata, and complete package checks |
| delivery adapter | delivery | platform, draft-only behavior, readback, and human authority |
| analytics and records | post-publish | approved writes, exact readbacks, and performance fields |

A binding is valid only when its path or tool exists, its trigger is specific,
and its output proof is named. Optional capabilities must say why they are
optional. A future publication should replace bindings, not rewrite the engine.
